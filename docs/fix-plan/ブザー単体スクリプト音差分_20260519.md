# ブザー単体スクリプト音差分 修正計画書

## 現状
`api/buzzer.py` は `example-code/1_output/2.2_PassiveBuzzer_zero.py` の音列を元に作成しているが、実行時の構造が完全一致していない。

主な差分:

- サンプルはモジュール読み込み直後に `tb = TonalBuzzer(17)` を作成している。
- `api/buzzer.py` は `play()` の中で `TonalBuzzer(BUZZER_PIN)` を作成している。
- サンプルは最後に `tb.stop()` のみ実行している。
- `api/buzzer.py` は最後に `buzzer.stop()` と `buzzer.close()` を実行している。
- 変数名やリスト定義の形もサンプルとは違う。

音列自体は同じだが、Thonny でサンプルと同じ鳴り方を確認したい用途では、余計な差分を残さない方がよい。

## 考えられる原因
1. `TonalBuzzer` の生成タイミングが違い、GPIO 初期化タイミングがサンプルと異なる。
2. 再生終了時に `close()` しているため、Thonny 上での再実行や GPIO 後処理の挙動がサンプルと異なる。
3. ユーザーが期待しているのは「参考コードと同じ音」なので、独自に整理した構造自体が不要。

## 対策
`api/buzzer.py` をサンプルと同じ構造に寄せる。

具体的には:

1. `tb = TonalBuzzer(17)` をグローバルに作成する。
2. `play(tune)` はサンプルと同じく `tb.play(note)` を呼ぶ。
3. 再生後は `tb.stop()` のみにする。
4. `tune` の内容はサンプルと同じ並びにする。
5. `main.py` は変更しない。

## 修正予定ファイル
- `api/buzzer.py`

## 確認方法
Thonny で以下の 2 ファイルをそれぞれ実行し、同じ鳴り方になることを確認する。

- `example-code/1_output/2.2_PassiveBuzzer_zero.py`
- `api/buzzer.py`

CLI での構文確認:

```bash
PYTHONPYCACHEPREFIX=/private/tmp/eq_rp_pycache python3 -m py_compile api/buzzer.py
```
