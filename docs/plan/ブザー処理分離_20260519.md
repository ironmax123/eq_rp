# ブザー処理分離 実装計画書

## 目的
`api/main.py` に直接書かれているパッシブブザー処理を `api/buzzer.py` に切り離し、`main.py` の責務を FastAPI 起動、LCD 表示、状態監視に寄せる。

## 現状
`api/main.py` には以下のブザー関連処理が混在している。

- `time` import
- `gpiozero.TonalBuzzer` import
- `BUZZER_PIN`
- `BUZZER_TUNE`
- `play_buzzer_tune()`
- `play_buzzer_alert()`
- 地震モード遷移時の `asyncio.create_task(play_buzzer_alert())`

このままだと `main.py` が肥大化し、LCD 表示とブザー通知の責務が混ざる。

## 実装方針

### 1. `api/buzzer.py` を新規作成
`api/buzzer.py` に以下を移動する。

- `import asyncio`
- `import time`
- `gpiozero.TonalBuzzer` の import と失敗時ログ
- `BUZZER_PIN = 17`
- `BUZZER_TUNE`
- 同期再生関数
- 非同期ラッパー関数

公開関数は `play_buzzer_alert()` のみにする。

### 2. `api/main.py` の修正
`main.py` からブザー固有処理を削除し、以下だけを import する。

```python
from buzzer import play_buzzer_alert
```

地震モード切り替え時の呼び出しは維持する。

```python
asyncio.create_task(play_buzzer_alert())
```

### 3. import 方針
`api/main.py` は既に `current_dir` を `sys.path` に追加しているため、`from buzzer import play_buzzer_alert` で読み込む。

`fastapi dev` の起動方法差分で問題が出る場合に備え、必要なら後続修正で `LCD1602` と同じファイルパスロード方式に寄せる。

### 4. 依存関係
`gpiozero` は既に `api/requirements.txt` に追加済みのため、今回の追加変更は不要。

## 修正予定ファイル
- `api/buzzer.py`
- `api/main.py`

## 確認方法
構文確認:

```bash
PYTHONPYCACHEPREFIX=/private/tmp/eq_rp_pycache python3 -m py_compile api/main.py api/buzzer.py
```

動作確認:

1. Raspberry Pi 側で `cd api`
2. `python -m pip install -r requirements.txt`
3. `fastapi dev`
4. 地震モード遷移時にブザーが一度だけ鳴ること
5. `gpiozero` がない環境では API 起動を止めず、ブザーだけスキップされること
