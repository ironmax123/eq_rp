# NHK風パッシブブザー連携 実装計画書

## 目的
`example-code/1_output/2.2_PassiveBuzzer_zero.py` の `TonalBuzzer` 実装を参考に、FastAPI 起動中に地震モードへ入ったタイミングでパッシブブザーを鳴らす。

LCD 表示と同様に Raspberry Pi ローカル起動を前提とし、GPIO が利用できない環境では API 起動自体を止めずにログ出力のみでスキップする。

## 参考コード
- `example-code/1_output/2.2_PassiveBuzzer_zero.py`
  - `gpiozero.TonalBuzzer`
  - GPIO pin `17`
  - `tb.play(note)` と `sleep(duration)` によるメロディ再生
  - 最後に `tb.stop()`

## 実装方針
`api/main.py` にブザー処理を追加する。

### 1. gpiozero の import
`gpiozero.TonalBuzzer` を `try-except` で読み込む。

- import 成功時: ブザー利用可能
- import 失敗時: `TonalBuzzer = None` とし、ログを出してブザー処理をスキップ

想定される失敗:
- FastAPI を起動している Python 環境に `gpiozero` が入っていない
- Raspberry Pi 以外の環境で GPIO が利用できない

### 2. ブザー初期化
GPIO17 を使って `TonalBuzzer(17)` を初期化する。

初期化は FastAPI import 時ではなく、実際にブザー再生する関数内または lifespan 開始後に行う。
これにより、GPIO 初期化失敗で FastAPI の import 全体が失敗することを避ける。

### 3. NHK風の通知音定義
サンプルの tune をベースに、地震通知として短く鳴るメロディを `BUZZER_TUNE` として定義する。

候補:

```python
BUZZER_TUNE = [
    ("C#4", 0.2),
    ("D4", 0.2),
    (None, 0.2),
    ("Eb4", 0.2),
    ("E4", 0.2),
    (None, 0.6),
]
```

長すぎると FastAPI のバックグラウンド処理を邪魔するため、まずは短い通知音にする。

### 4. 非同期ループへの組み込み
既存の `lcd_update_loop()` は `state.is_eq_mode` と `last_mode` を見ている。

この構造を利用し、`last_mode != "eq"` で地震モードへ切り替わった瞬間だけブザーを鳴らす。

同じ地震モード中に 1 秒ごとに鳴り続けないようにする。

### 5. ブザー再生方法
`gpiozero.TonalBuzzer` の `play()` と `time.sleep()` は同期処理なので、FastAPI のイベントループを塞がないように `asyncio.to_thread()` で別スレッド実行する。

実装イメージ:

```python
asyncio.create_task(play_buzzer_alert())
```

`play_buzzer_alert()` 内で `asyncio.to_thread(play_buzzer_tune)` を呼ぶ。

### 6. エラーハンドリング
ブザー処理の失敗は API や LCD 表示を止めない。

出力するログ:
- `TonalBuzzer import failed: ...`
- `Buzzer alert skipped because TonalBuzzer is not available.`
- `Buzzer init error: ...`
- `Buzzer play error: ...`

### 7. 依存関係
`api/requirements.txt` に `gpiozero` を追加する。

Raspberry Pi 側では以下で反映する。

```bash
cd api
python -m pip install -r requirements.txt
```

## 修正予定ファイル
- `api/main.py`
- `api/requirements.txt`

## 確認方法
Raspberry Pi 上で FastAPI を起動する。

```bash
cd api
fastapi dev
```

確認項目:

1. 起動時に `TonalBuzzer` import 失敗または成功後のブザー関連ログが確認できること。
2. `state.is_eq_mode` が `False` の待機中はブザーが鳴らないこと。
3. `state.is_eq_mode` が `True` に切り替わったタイミングで一度だけ通知音が鳴ること。
4. ブザー処理に失敗しても FastAPI と LCD 表示が継続すること。

## 注意点
- GPIO pin はサンプルに合わせて `17` とする。
- ブザー音は短くし、地震モード継続中に鳴り続けないようにする。
- Raspberry Pi 以外の環境ではスキップされる前提とする。
