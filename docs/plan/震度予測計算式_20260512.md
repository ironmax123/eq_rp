# 地震速報からの都道府県別震度予測 実装計画（計算式アプローチ）

## 1. 概要と目的
緊急地震速報（EEW）で取得できる「震源（緯度・経度・深さ）」と「マグニチュード」を用いて、各都道府県の予測震度を自前で計算し、Flutterアプリ側で地図の色分けを行うためのバックエンド（FastAPI）実装計画書です。
本計画では、物理的・経験的な法則に基づく**「距離減衰式（アプローチA）」**を採用し、最速で妥当な震度予測モックを構築します。

## 2. 採用する計算式とその根拠（ソース）
本実装では、日本の地震動予測において最も標準的に用いられている**「司・翠川（1999）の距離減衰式」**を採用します。気象庁の緊急地震速報における強震動予測や、防災科学技術研究所（J-SHIS）のハザードマップ等でもこの基本ロジックが用いられています。

*   **信頼できるソース:**
    *   司 宏俊, 翠川 三郎 (1999): 断層最短距離を用いた最大加速度・最大速度の距離減衰式, 日本建築学会構造系論文集, Vol.64, No.523, pp.63-70.
    *   防災科学技術研究所 (NIED) J-SHIS 地震動予測地図 計算手法
    *   気象庁 震度予測手法（緊急地震速報等における活用）

**なぜこの計算式になるのか（式の物理的背景）：**
地震による揺れ（地震動）は、震源（断層）で放出されたエネルギー（マグニチュード）に比例して大きくなり、震源から波として伝わるにつれて距離の二乗や内部減衰によってエネルギーが拡散し、弱くなります（距離減衰）。また、実際の地表の揺れは、深い硬い岩盤（基盤）から地表の柔らかい土の層（表層地盤）を伝わる際に増幅されます。
これらを経験的（過去の観測データ）に数式化したものが本計算式であり、「①マグニチュードと距離から硬い岩盤での揺れを計算」→「②地盤の柔らかさで増幅」→「③揺れの速度を震度に変換」という理にかなったステップを踏みます。

## 3. 計算ロジックの詳細（ステップ）

実装は以下のステップで計算を行います。

### ステップ1: 震源からの距離(X)の算出
各都道府県の代表地点（県庁所在地など）の緯度・経度と、EEWの震源の緯度・経度から、距離を計算します。
（本来は「断層面からの最短距離」ですが、即時予測では断層面が不明なため「震源距離」または「震央距離」と「深さ」を用いて近似します）

### ステップ2: 基準基盤上の最大速度 ($PGV_{b600}$) の計算
司・翠川(1999)の式を用いて、S波速度600m/s相当の硬質地盤（基準基盤）における最大速度(PGV: Peak Ground Velocity)を求めます。

$$ \log_{10} PGV_{b600} = 0.58 M_W + 0.0038 D + d - 1.29 - \log_{10} (X + 0.0028 \times 10^{0.50 M_W}) - 0.002 X $$

*   $M_W$: モーメントマグニチュード（気象庁マグニチュードから近似換算、またはそのまま使用）
*   $X$: 震源距離 (km)
*   $D$: 震源深さ (km)
*   $d$: 地震タイプ別係数（初期実装では不明なため平均的な `0` とする）

### ステップ3: 工学的基盤への補正 ($PGV_{b400}$)
基準基盤から、より浅い工学的基盤（S波速度400m/s相当）への増幅を考慮します。一般的に固定の増幅係数（約1.31）を掛けます。

### ステップ4: 表層地盤増幅率(ARV)を考慮した地表のPGV ($PGVs$) の算出
地表の揺れは、その土地の地盤の柔らかさによって増幅されます。
$$ PGVs = PGV_{b400} \times ARV $$
*   $ARV$: 表層地盤増幅率。
*   ※初期実装フェーズでは、データが揃っていないため全県一律で `ARV = 1.0` (または一般的な平均値 `1.5` 程度) と仮定し、将来的に県ごとの平均ARV係数を持たせることで精度を上げます。

### ステップ5: 計測震度 ($I$) への換算
翠川・他（1999）などが提案する式を用いて、地表の最大速度(PGVs)を気象庁の「計測震度」に変換します。
$$ I = 2.68 + 1.72 \log_{10} PGVs $$

この計算された $I$ を四捨五入や閾値判定により、震度1〜7の階級（例: $I < 0.5$ は震度0、$0.5 \le I < 1.5$ は震度1 ... $4.5 \le I < 5.0$ は震度5弱 等）にマッピングします。

## 4. FastAPIでの実装方針

### 4-1. エンドポイントと処理フロー
*   **対象API**: `api/src/routes/handler/` 配下の既存のEEW配信用WebSocket/SSEエンドポイント、または新規の計算処理モジュール。
*   **処理フロー**:
    1. 外部からEEW情報（緯度 `lat`、経度 `lon`、深さ `depth`、マグニチュード `mag`）を受信。
    2. サーバー内に保持している「47都道府県の代表座標リスト」をループ処理。
    3. 各座標に対して、上記のステップ1〜5の計算式（Python関数）を適用し、予測震度階級を算出。
    4. 結果を `{ "tokyo": "3", "osaka": "1", ... }` のような形式でEEWレスポンスの `areas` または `intensity_prediction` フィールドに付与してフロントエンドへ配信。

### 4-2. 必要なデータ構造（モック用）
Pythonの辞書またはPydanticモデルで、47都道府県の代表緯度経度を静的に定義します。
```python
PREFECTURE_COORDS = {
    "hokkaido": {"lat": 43.0620, "lon": 141.3543},
    "aomori": {"lat": 40.8246, "lon": 140.7399},
    # ...全47都道府県
}
```

## 5. 今後の精度向上のためのフェーズ分け
*   **フェーズ1 (今回実装)**:
    *   計算式ベースで47都道府県の予測震度を算出。地盤増幅率(ARV)は一律固定。
    *   目的: システムがエンドツーエンドで動き、Flutter側で地図の色塗りが即時に行われる基盤を作る。
*   **フェーズ2 (精度向上)**:
    *   J-SHISのデータを元に、各都道府県の代表的な「表層地盤増幅率(ARV)」をCSV/JSON化し、計算式に組み込む（平野部＝揺れやすい、山間部＝揺れにくい を反映）。
*   **フェーズ3 (AIモデル化の検討)**:
    *   もし計算式で「異常震域」などの対応に限界を感じた場合、本モジュールを過去CSVで学習したMLモデル（アプローチB）の推論モジュールに置き換える。
