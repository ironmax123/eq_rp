# LCD表示不具合 修正計画書

## 現状と課題
実装したLCD1602連携機能において、「文字列が表示されない」という事象が発生している。

### 考えられる原因
1. **バックグラウンドタスクの停止**: `LCD1602.init` や `write` 内で例外（I2C通信エラー等）が発生し、監視タスク `lcd_update_loop` が無言で終了している。
2. **インポート失敗**: `HAS_LCD` が `False` になっている、あるいはインポート時に `smbus2` 等の依存関係でエラーが出てタスクが起動していない。
3. **日本語表示の不可**: LCD1602（HD44780系）は標準で日本語（UTF-8）をサポートしておらず、地名などの日本語を表示しようとして不具合が起きている可能性がある。
4. **I2Cアドレス等の不一致**: 環境によってI2Cアドレスが `0x27` ではない、あるいはコントラスト等のハードウェア設定の問題。

## 対策案

### 1. タスクの状態監視とエラーハンドリングの強化
タスクが例外で終了しないよう、ループ全体を `try-except` で囲み、エラー内容を標準出力（ログ）に書き出すようにします。これにより、何が原因で止まっているか、あるいは動いているかを確認可能にします。

### 2. 日本語表示の回避
LCD1602はASCII文字のみを想定しているため、表示内容をアルファベットのみに制限します。
- 地名は暫定的に固定メッセージや "Earthquake!" などの英字に変更します。
- 待機中メッセージなどもすべてASCII文字であることを徹底します。

### 3. インポート状態の明示
`HAS_LCD` が `False` の場合に、コンソールに警告を出すようにします。

## 修正後のコードイメージ（api/main.py）

```python
async def lcd_update_loop():
    if not HAS_LCD:
        print("LCD1602 module not found or failed to import. LCD update skipped.")
        return
    
    try:
        LCD1602.init(0x27, 1)
        print("LCD1602 initialized successfully.")
    except Exception as e:
        print(f"LCD1602 init failed: {e}")
        return

    last_mode = None
    while True:
        try:
            state = get_cache_state()
            if state.is_eq_mode:
                if last_mode != "eq":
                    LCD1602.clear()
                    last_mode = "eq"
                # 日本語を避け、ASCII文字のみを表示
                LCD1602.write(0, 0, "EQ DETECTED!")
                intensity = state.kmoni_cache_data.get('earthquakes')[0].get('maxIntensity', '-') if state.kmoni_cache_data else "-"
                LCD1602.write(0, 1, f"Max Int: {intensity}")
            else:
                if last_mode != "standby":
                    LCD1602.clear()
                    LCD1602.write(0, 0, "Status:")
                    LCD1602.write(0, 1, "Standby")
                    last_mode = "standby"
        except Exception as e:
            print(f"LCD update error: {e}")
        
        await asyncio.sleep(1)
```

## 確認事項
- `LCD1602.py` の `init` メソッドが `IOError` を投げる実装になっているため、例外処理が必須です。
- まずは英字メッセージが正しく表示されるかを確認したいです。
