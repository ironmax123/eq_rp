# バグ修正計画書: 予測震度が maxIntensity を下回る問題（内陸地震ほか）

## 発生日: 2026-05-12

## 1. バグの概要

内陸地震など、震源が県庁所在地（代表座標）から離れた場所にある場合、
距離減衰式が**震源最近傍の都道府県でも maxIntensity より低い予測値を返す**現象が発生する。

**再現例（熊本地震的シナリオ / M7.3, 深さ11km, maxIntensity=7）:**
```
kumamoto : 震度6-  ← 震源から7.0kmなのに、maxIntensity=7 より低い
saga     : 震度5-
oita     : 震度4
```

## 2. 根本原因の分析

### 主因: 代表座標が「県内の最大揺れ地点」ではない

計算式は各都道府県の **県庁所在地の座標**を代表点として使用している。  
内陸地震では震源が県内の山間部や農村部にある場合が多く、
県庁は震源から十数〜数十km離れていることがある。  

→ 計算式は「県庁所在地での揺れ」を計算するため、
  「県内の観測点で記録された最大震度」より小さくなる。

### 副因: 平野部・沿岸部に県庁が集中している

特に日本の県庁所在地は平野部・沿岸部に偏っているため、
内陸震源からの距離が過大になりやすい。

## 3. 対策方針

### 採用案: 「最近傍都道府県フロア」方式

震源に最も近い都道府県を距離で特定し、
その都道府県の予測震度を `max(予測値, maxIntensity)` に引き上げる。

**理由:**
- 震源に最も近い都道府県は、物理的に最も強く揺れた可能性が最も高い。
- `maxIntensity` は「どこかが観測した最大値」であり、
  その候補として最近傍都道府県が最も合理的。
- 1都道府県のみに適用するため、過度な引き上げにならない。
- 既存のキャップ処理（上限）と組み合わせても矛盾しない
  （キャップ後に適用するのではなく、同じステップで判定する）。

### 不採用案: 全都道府県にフロアをかける
→ 「遠方の都道府県が最大震度と同じ強さ」になり、現実と大きく乖離するため不採用。

### 不採用案: 予測最大値が maxIntensity に達するまで係数を調整する
→ 計算式の物理的整合性が崩れるため不採用。

## 4. 修正箇所

### `formula.py` の `predict_prefecture_intensity` のみ変更

```python
def predict_prefecture_intensity(
    eq_lat, eq_lon, depth_km, magnitude,
    max_intensity: str | None = None,
) -> list[dict]:
    ...
    # 全47都道府県の計算が終わった後:
    # 1. 震源に最も近い都道府県を特定する（surface_dist が最小）
    # 2. その都道府県の intensity を max(predicted, max_intensity) に引き上げる
    #    ただし上限キャップも維持する（矛盾しないよう max_intensity が上限かつ下限になる）
```

**具体的な処理フロー:**
```
1. 各都道府県の (pref, intensity, surface_dist) を一時リストに格納
2. surface_dist が最小の都道府県 = closest_pref を特定
3. closest_pref の intensity について:
   - _INTENSITY_ORDER[intensity] < _INTENSITY_ORDER[max_intensity] の場合
   - intensity = max_intensity に引き上げ（フロア）
4. 震度0の都道府県を除外して返す
```

## 5. 修正後の期待動作

| シナリオ | 修正前 | 修正後 |
|---------|--------|--------|
| M7.3 熊本内陸 (maxIntensity=7) / kumamoto (7km) | 震度6- | 震度7 |
| M7.3 首都直下 (maxIntensity=6-) / saitama (最近傍) | 震度6- | 震度6- (変化なし) |
| maxIntensity="" (不明) | 変化なし | 変化なし |

## 6. 注意事項

- 適用対象は「**震源に最も近い1都道府県のみ**」。他の都道府県は従来通り距離計算結果を使用。
- `max_intensity` が空・不正値の場合はフロア処理をスキップする（安全側）。
- 既存の上限キャップ `_cap_intensity()` とは別関数 `_floor_intensity()` として実装する。
